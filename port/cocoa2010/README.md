# Native Cocoa 2010 core UI

Experimental, opt-in UI port, developed on the `cocoa-2010-ui` branch and layered onto the optimized Snow Leopard pass40 build of Chromium 124.0.6367.207. It replaces the visible Views core chrome with native AppKit controls. The omnibox editor is a real `NSTextView`, with native selection, undo and composition, connected to the current omnibox model.

The historical source is pinned to **Chromium 7.0.517.41**. Original files, XIBs and artwork are retained under `upstream/`; `upstream.json` records their source URL and SHA-256. The tab Bézier path, cell drawing, toolbar geometry, tab sizes/overlap, close-button drawing and original PDF/PNG artwork come from those sources. The toolbar gradient retains the old window-relative calculation and GTM Lab luminance treatment. `upstream-gtm/` retains the copyright-2009 helper from Chromium's vendored GTM. The glossy Chromium application icon is the original Chromium 7 `app.icns` and is used in both UI modes. Historical in-app artwork is used only by the enabled 2010 UI.

This is a selective port, not a wholesale transplant of the old browser controllers. Their obsolete C++ browser APIs are replaced by `browser_adapter.mm`, which observes the current `TabStripModel` and transfers the actual `WebContents` for tab moves. Native window traffic lights and the original textured/unified style use AppKit’s actual `NSGrayFrame` on Snow Leopard, bypassing both modern frame subclasses. The 36-point tab strip and 64-point control inset follow `BrowserWindow.xib` and `TabStripController`. The historical Cocoa controls own drawing and editing; the transparent Views toolbar remains as a model and page-info/permission bubble host.

The main menu, wrench menu and tab context menu retain **Chromium 124's features**. The wrench uses `MenuControllerCocoa` and a native `NSMenu`; the Zoom/Edit button rows become ordinary submenus with the same current commands and accelerators. The bookmarks bar now uses ported Cocoa button cells, sizing, overflow layout, folder artwork, drag/drop indicators and the original toolbar compression. Its controller adapts those methods to the current bookmark model and current bookmark context-menu commands. Autocomplete uses the original Chromium 7 native `NSWindow`, `NSMatrix` and button-cell drawing, adapted to Chromium 124's result model and current actions. Compact rows use the old font sizing, icon placement and selection drawing, with a native shadow; page-info/permission bubbles, settings, rendering and other transient UI keep their current implementations. Native field bounds anchor the current omnibox and page-info popups. Modern toolbar chips and extension buttons are not recreated in the compact historical toolbar; their menu/settings features remain current.

## Build in the provisioned workspace

Apply the pinned Legacy and Snow Leopard patches first, as described in the repository's `BUILDING.md`. This feature installer targets that provisioned Chromium 124 source, not a clean-machine bootstrap.

```sh
python3 port/cocoa2010/install.py --source /path/to/chromium-124.0.6367.207
/path/to/toolchain/bin/ninja -C /path/to/chromium-124.0.6367.207/out/SnowLeopard -j12 chrome
```

The installer dry-runs the patch first, recognizes a wholly applied patch on repeated runs, and preserves a partially modified tree rather than guessing. `overlay/` provides the native source files and original assets. The feature patch changes thirty Chromium files, including GN resource/source lists, frame layout, native focus, model text forwarding and popup anchors. `chrome://flags/#cocoa-2010-ui` exposes **2010 UI (Experimental)** with Default, Enabled and Disabled choices. Chromium stores that choice in Local State and applies it on relaunch; it is registered as a non-expiring preference. Default and Disabled use the existing modern UI; Enabled supplies `--enable-cocoa-2010-ui` on relaunch. An explicit `--disable-cocoa-2010-ui` wins if both switches are present. `chrome://flags/#aqua-scrollbars` independently exposes **Aqua Scrollbars (Experimental)**, disabled by default. It uses the standard `AquaScrollbar` feature, including propagation to renderer processes; `--enable-features=AquaScrollbar` enables it without enabling the historical core UI. Both flags are non-expiring. The historical application icon is unconditional.

The same drawing/editing controls can be compiled into a small modern-host preview:

```sh
port/cocoa2010/build-preview.sh /path/to/chromium-124.0.6367.207
```

That preview is a drawing aid; it does not verify Chromium integration or Snow Leopard behavior.

The omnibox uses the original Mac PDF globe, magnifier, history and HTTPS artwork, drawn at 19 points with the original five-point field inset. The first stationary click selects all; subsequent native editor clicks place the caret. Full URLs retain their scheme and path. The original host emphasis, green HTTPS scheme, and dangerous-scheme treatment use current security state, and the line height comes from AppKit as in Chromium 7. The transparent Views model host has its caret disabled so its blink timer cannot outlive native editor focus. HTTPS state still comes from Chromium 124. Live tab dragging follows the old controller’s placeholder/gap layout and target-frame cache; only changed targets start animations. The new-tab button draws its original normal/hover/pressed artwork, and loading uses Chromium 7’s filmstrip throbber instead of an AppKit progress indicator. Tab title text includes the original field’s two-point inset. The new-tab PDF draws at its original natural size inside the 40×27 hit target. The cursor-following tab glow and its show/hold/hide timing are ported from `TabView`. Tab movement uses an explicit 125ms AppKit frame animation, with Core Animation actions disabled at each frame. New tabs enter from below the tab strip’s clipped horizon, as in the original controller. Backing layers remain attached during selection and reordering. The user subsequently confirmed that the drag fade no longer appears.

When the separate Aqua flag is enabled on Snow Leopard, unstyled legacy scrollbars are drawn by the system’s actual `HIThemeDrawTrack`, recorded into Chromium’s paint list. The legacy double-end arrow hit regions, reduced track and minimum thumb size are restored using the Mac non-overlay WebCore geometry retained in `upstream-webcore/` (the later Chromium 49 implementation of the same legacy Carbon path). Blink supplies scrolling and button repeat timers. The native path preserves the actual control bounds, scroll range and value and draws the complete track, arrows and knob together, using the original non-overlay WebCore approach. It asks `HIThemeGetTrackThumbShape` for knob travel and hit geometry. A separate compositor thumb texture would move the pattern and offset the rounded ends, so Aqua is repainted as a complete control when its scroll value changes. Explicit CSS scrollbar colors retain the current separate paint path. Window activation invalidates cached Aqua artwork, and the native active, inactive, disabled and pressed states are forwarded to HITheme. The top-level viewport reserves the native resize-handle corner when only one scrollbar is present. Explicit CSS scrollbar colors keep the current custom-color path.

## Original binary reference

An official Mac snapshot, revision **60026**, was downloaded from Google's Chromium snapshot archive. Its actual version is **7.0.530.0**, minimum OS 10.5. It is close to the pinned stable source and runs on the target 10.6.8 Mac. `reference-build.json` records the URL and archive hash. The binary is not added to Git or redistributed in the port package.

On the target Mac, the original lives at `~/Snowium/modern-port/builds/reference-chromium-7-r60026/chrome-mac/Chromium.app`; the experimental port lives at `~/Snowium/modern-port/builds/124-cocoa2010-20261007/Chromium.app`. They were launched with separate task profiles, leaving `/Applications/Chromium.app` untouched. The target Desktop’s `Snowium 2010.command` launches the experimental binary directly with its isolated profile. Crash Reporter/Finder relaunches can omit that profile and hand off to the already running modern Chromium; the saved Enabled choice in the isolated profile enables the historical UI. A fresh profile starts with the modern UI and modern scrollbars.

## Validation and remaining work

The current experimental build compiles, targets 10.6 and runs on the Snow Leopard Mac. All ten renderer integration checks pass, along with renderer keyboard input, clicking and wheel scrolling. Source hashes, pinned patch checks and installer idempotence pass. The historical application icon and core UI use the isolated development bundle and profile; `/Applications/Chromium.app` is untouched.

Both experimental flags were exercised through the native `chrome://flags` UI. All four combinations of Default and Enabled persisted across relaunches and independently selected the modern or historical core UI and modern or Aqua scrollbars. Disabled also restored the current core UI. The original application icon is shared by both modes. The task profile is left with both preferences Enabled. [Runtime captures and the isolation audit](validation/20261008/README.md) record the checks.

The pass25 build fixes stale active/inactive tab artwork by invalidating the individual AppKit backing layers on key-window, main-window and application activation changes. A redraw of the parent alone left child layers cached. The original Chromium 7 inner highlight strokes remain, with their explicit one-point widths. Three application activation cycles and two focus cycles between experimental browser windows consistently updated both selected and unselected tab shading on 10.6.8. [Screenshots and sampled states](validation/20261008/README.md) record those checks.

The asymmetric upper window corners were caused by the traffic-light cutout sharing the rounded clip's nonzero-winding path. Separate intersecting clips preserve the native frame at both corners; target screenshots confirm the formerly square left corner is rounded.

Pass26 replaces the tabs' overlapping rectangular hover tracking areas with Chromium 7 TabStripController's single tracking area and hit-test dispatch. Only one tab owns hover input at a time, including over close buttons; tracking updates re-evaluate the owner when tabs move beneath a stationary cursor. The original glow show/hold/hide timing is retained. The user confirmed that the overlap is fixed but reported that hover remains slow. The supplied tab-highlight comparison is assessed separately below.

Pass30 fixes the measured hover refresh bottleneck: one 60 Hz strip timer advances fading tabs together, the original default toolbar gradients are cached, and hover redraws invalidate the existing AppKit tab backing layer directly. This avoids repeatedly repainting and synchronizing the native window frame under a translucent tab. The old 200 ms rise, 20 ms hold, and 400 ms decay remain. On the actual Snow Leopard Mac, settled-page redraw spacing improved from 52 ms median / 83 ms p95 to 16.7 ms median / 17.4 ms p95 across 18 pointer movements. [Raw timings and profiling findings](benchmarks/hover-20261008/README.md) distinguish those redraw measurements from presentation timing and startup stalls. Temporary timing probes are removed in the clean build. The user confirmed that hover now feels smooth and close to Chromium 7.

Pass31 restores native dragging throughout the empty 36pt grey tab strip, including the portion that overlaps the modern content host. It ports the historical new-tab hit polygon and uses Snow Leopard's move-only opaque region to exclude the toolbar and page. Native input and window bounds confirm lower-strip dragging and a stationary toolbar drag. The fine inner highlight is present in a fresh selected-tab capture; both historical source versions draw it only on selected tabs. The supplied comparison appears to use different selection states, which remains unconfirmed. [Source findings and captures](validation/20261008/README.md) record the distinction.

Native screenshots taken before the latest animation changes verified the window gradient and tab/toolbar join against Chromium 7, the corrected natural-size new-tab artwork, the unified bookmarks-bar gradient across window activation, first-click text selection, current bookmark context-menu commands, and the square popup's border and native shadow. The user confirmed Cmd-L, copy/paste, first-click selection, the mouse-following tab glow and live tab reordering. The hidden Views caret timer that caused the address-bar crash is disabled; later address use kept the browser alive.

The Aqua path was checked on a dedicated renderer fixture against direct `HIThemeDrawTrack` output from 10.6.8. Vertical and horizontal controls at scroll positions 0, 100, 500 and the end match the native knob geometry, rounded ends and pattern alignment. Their blue interiors have small color differences through the browser's rendering pipeline, so this is not a claim of exact RGB parity. The pressed upper arrow in the bottom button pair matches the direct native drawing exactly. Both vertical and horizontal arrow hit regions move the fixture from 100 to 60 or 140; thumb dragging reaches 447 and wheel scrolling reaches 200. The top-level viewport retains the native resize-handle corner gap. Thin native controls draw at 11px and scroll normally; CSS-colored controls keep their current appearance and pass wheel and track-click checks without entering the Aqua arrow path.

The user confirmed that the dragged-tab fade no longer appears. The current build suppresses AppKit view animation defaults and backing-layer actions while retaining explicit frame/hover animation, and flushes display updates inside the native drag tracking loop. It retains AppKit backing layers: an attempted replacement layer hid tab artwork on 10.6 and was removed; target screenshots confirm the tabs are visible again. New-tab animation still needs visual acceptance.

The address-field mismatch was traced to a cleared native bezel flag. Decoding the original Toolbar.xib cell flags on 10.6.8 confirmed a bezeled cell; the current port restores that flag and removes the manual editor container insets. Native screenshot comparisons show the corrected editing baseline and left inset against Chromium 7. The standard native window buttons remain attached during controller cleanup, avoiding the dangling NSThemeFrame button references found in shutdown crash reports. Their original AppKit targets/actions are retained: retargeting `performZoom:` to the window caused recursive button clicks on 10.6 and was removed. Multiple diagnostic `Browser.close` shutdowns completed cleanly, and the native green button now zooms and restores the target window without hanging. Native minimize and close-button paths remain unverified.

The inflated Views autocomplete popup was replaced by the Chromium 7 native popup port. Native rapid-typing checks no longer showed the stale page-pixel artifacts in its rows. The original compact layout and AppKit shadow are retained; current result types and commands use the 124 model. Native IME and less common result types remain unverified.

[Scrolling benchmarks on the actual Snow Leopard Mac](benchmarks/scroll-20261008/README.md) pair a simple compositor scroller with Google Fonts. The native painter takes about 0.35–0.7 ms, but main-thread position handoff reached 620 ms while Google Fonts did layout work. The page continued scrolling asynchronously. An earlier forced-main-thread trial increased page latency and was rejected; it is absent from current source. The temporary scroll-reason tracing is removed; ordinary lightweight paint trace scopes remain. Aqua refresh lag is unresolved; an independent asynchronous resource refresh has not yet been implemented.

This source experiment is not packaged or ready for release. Native IME, undo, multi-window tab transfer, advanced tabs and full visual parity remain unverified. The historical NTP detached bookmarks-bar presentation is not yet ported; the bar currently follows Chromium 124's visibility state. Bookmark menu commands retain current features; old controller code that depended on obsolete browser APIs is adapted rather than transplanted wholesale.
